# Architecture\n\nPipeClean is split into a toolchain and a runtime.\n\n## Toolchain\n\n### tools/sm83.py\n\nDefines the Game Boy SM83 instruction set and instruction decoding support.\n\n### tools/dis.py\n\nProvides disassembly support for inspecting Game Boy machine code.\n\n### tools/discover.py\n\nHelps discover executable regions and references useful to recompilation.\n\n### tools/recomp.py\n\nThe static recompilation/lifting stage. It translates discovered SM83 code into C for the native runtime.\n\n## Runtime\n\nThe runtime/ directory contains the native execution environment, including CPU/emulation support, cartridge and mapper handling, memory, PPU/video behavior, audio, input, and rendering.\n\nThe runtime is separated from generated game code so platform and presentation work can evolve independently.\n\n## SML2 and MBC1\n\nSuper Mario Land 2 is larger than a simple 32 KiB ROM and uses MBC1 banking. The current development path therefore supports an interpreter/runtime route for the full cartridge rather than assuming a flat ROM-only address space.\n\n## Widescreen behavior\n\nThe original Game Boy viewport is 160 pixels wide. A wider desktop viewport exposes additional world space, but the original game may only activate objects near the original right edge.\n\nFor SML2, the activation calculation around bank 2 address $401C uses a 96-pixel right-side margin. The widescreen compatibility hook preserves the original instruction stream while extending that effective margin at runtime.\n\nConceptually:\n\n    original:    object activation = camera + 0x60\n    widescreen: object activation = camera + 0x60 + right_extension\n\nDespawning behavior is intentionally kept separate so the compatibility change does not unexpectedly alter object lifetime on the left side.\n\n## Testing\n\nThe SML2 widescreen regression test lives under tests/. It checks the compatibility-hook behavior without requiring a commercial ROM to be committed to the repository.
